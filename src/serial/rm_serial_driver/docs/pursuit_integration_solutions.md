# 自瞄追击功能集成方案

## 功能需求分析

### 自瞄功能（视觉模块）
- ✅ 目标检测：`armor_detector` 检测装甲板
- ✅ 目标跟踪：`armor_tracker` 跟踪目标
- ✅ 弹道解算：`armor_solver` 计算云台控制命令
- ✅ 发布话题：
  - `/tracker/target` - 目标信息（位置、速度、ID等）
  - `armor_solver/cmd_gimbal` - 云台控制命令

### 追击功能（导航模块）
- ✅ 路径规划：NAV2 规划路径
- ✅ 底盘控制：`sentry_control` 控制底盘移动
- ⚠️ **缺失**：接收目标信息并生成追击命令

## 方案对比

### 方案1：保留两个容器（推荐）⭐

#### 架构
```
┌─────────────────────┐              ┌─────────────────────┐
│   self_nav          │              │   rm_vision         │
│   Container         │              │   Container         │
│                     │              │                     │
│  ┌───────────────┐  │              │  ┌───────────────┐  │
│  │ pursuit_node  │  │              │  │ armor_tracker │  │
│  │ (新增)        │  │              │  │               │  │
│  │               │  │              │  │ 发布:         │  │
│  │ 订阅:         │  │              │  │ /tracker/     │  │
│  │ /tracker/     │◄─┼──ROS2话题────┼──│ target        │  │
│  │ target        │  │              │  └───────────────┘  │
│  │               │  │              │                     │
│  │ 发布:         │  │              │                     │
│  │ cmd_vel       │  │              │                     │
│  └───────┬───────┘  │              └─────────────────────┘
│          │          │
│          ▼          │
│    sentry_control   │
│    (现有)          │
└─────────────────────┘
```

#### 优点
1. ✅ **模块分离**：视觉和导航独立开发、测试、部署
2. ✅ **资源隔离**：CPU/内存资源独立，互不影响
3. ✅ **易于维护**：修改一个模块不影响另一个
4. ✅ **可扩展性**：可以独立升级或替换模块
5. ✅ **ROS2跨容器通信**：通过话题通信，延迟低（通常<10ms）

#### 缺点
1. ⚠️ **需要配置ROS2 DDS**：确保两个容器能通信
2. ⚠️ **需要共享TF树**：如果使用TF进行坐标转换

#### 实现要点
1. **新增追击节点**（在 self_nav 容器）：
   - 订阅 `/tracker/target` 话题
   - 根据目标位置计算底盘速度
   - 发布 `cmd_vel` 或修改 `sentry_control` 的输入

2. **ROS2通信配置**：
   - 使用相同的 `ROS_DOMAIN_ID`
   - Docker 使用 `--network host` 或配置 DDS

3. **坐标转换**（如需要）：
   - 使用 TF2 进行坐标转换
   - 确保两个容器共享 TF 树

#### 数据流
```
视觉模块检测目标
  ↓
发布 /tracker/target (包含位置、速度)
  ↓
ROS2话题跨容器传输
  ↓
pursuit_node 订阅目标信息
  ↓
计算追击速度
  ↓
发布 cmd_vel
  ↓
sentry_control 控制底盘
```

### 方案2：整合到一个容器

#### 架构
```
┌─────────────────────────────────────┐
│   unified_container                │
│                                    │
│  ┌──────────────┐  ┌─────────────┐│
│  │ rm_vision    │  │ self_nav    ││
│  │ modules      │  │ modules     ││
│  └──────┬───────┘  └──────┬──────┘│
│         │                 │       │
│         └────────┬─────────┘       │
│                  │                │
│         ┌────────▼────────┐      │
│         │ pursuit_node    │      │
│         └─────────────────┘      │
└─────────────────────────────────────┘
```

#### 优点
1. ✅ **通信延迟更低**：同进程通信，延迟<1ms
2. ✅ **共享资源更方便**：TF、参数服务器等
3. ✅ **部署简单**：只需一个容器

#### 缺点
1. ❌ **耦合度高**：两个模块绑定在一起
2. ❌ **资源竞争**：CPU/内存共享，可能互相影响
3. ❌ **维护困难**：修改一个模块需要重新构建整个容器
4. ❌ **扩展性差**：难以独立升级或替换模块

### 方案3：混合方案（核心功能整合，辅助功能分离）

│                     │              │                     │

#### 适用场景
- 自瞄和追击需要紧密耦合
- 其他功能（如地图构建、调试工具）可以分离

## 推荐方案：方案1（保留两个容器）

### 理由
1. **当前架构已支持**：串口桥接节点已经实现了跨容器通信
2. **延迟可接受**：ROS2话题通信延迟通常<10ms，对追击功能足够
3. **模块化设计**：符合ROS2的设计理念
4. **易于调试**：可以独立测试和调试每个模块

### 实现步骤

#### 1. 创建追击节点（在 self_nav 容器）

**节点名称**：`pursuit_controller_node`

**功能**：
- 订阅 `/tracker/target` 话题（`auto_aim_interfaces::msg::Target`）
- 根据目标位置计算底盘速度
- 发布 `cmd_vel` 或修改 `sentry_control` 的输入

**输入**：
- `/tracker/target` - 目标信息（位置、速度、ID等）

**输出**：
- `cmd_vel` 或 `pursuit_cmd_vel` - 追击速度命令

**算法**：
- 根据目标位置（相对于机器人）计算追击方向
- 考虑目标速度进行预测
- 限制最大速度，避免碰撞

#### 2. 配置ROS2跨容器通信

**Docker配置**：
```bash
# self_nav 容器
docker run --network host \
  -e ROS_DOMAIN_ID=0 \
  ...

# rm_vision 容器
docker run --network host \
  -e ROS_DOMAIN_ID=0 \
  ...
```

**或使用DDS配置**：
- 配置 `FASTDDS_DEFAULT_PROFILES_FILE` 或 `RMW_IMPLEMENTATION`

#### 3. 坐标转换（如需要）

如果目标位置在相机坐标系，需要转换到机器人坐标系：
- 使用 TF2 进行坐标转换
- 确保两个容器共享 TF 树
- 或使用 `geometry_msgs::msg::TransformStamped` 手动转换

#### 4. 集成到现有控制流程

**选项A**：直接发布 `cmd_vel`
```
pursuit_node → cmd_vel → sentry_control → cmd_vel_control_result
```

**选项B**：修改 `sentry_control` 支持目标输入
```
pursuit_node → pursuit_cmd_vel → sentry_control (修改后) → cmd_vel_control_result
```

**选项C**：使用行为树或状态机
```
状态机判断：
  - 有目标 → pursuit_node 控制
  - 无目标 → NAV2 路径规划控制
```

## 性能分析

### 通信延迟
- **ROS2话题（跨容器）**：通常 5-20ms
- **ROS2话题（同容器）**：通常 1-5ms
- **串口通信**：通常 10-50ms

### 实时性要求
- **自瞄**：需要高实时性（<50ms延迟）
- **追击**：可以接受稍高延迟（<100ms延迟）

**结论**：ROS2跨容器通信的延迟对追击功能完全可接受。

### 优势

- 延迟可接受（<20ms）
